# 架構

## 分層

```
┌──────────────────────────────────────────────────────────────┐
│ variants/<名稱>/main.js   startApp({ plugins: [...] })        │  各版本 = 核心 + 外掛
├──────────────────────────────────────────────────────────────┤
│ plugins/*                 只透過 api（src/app/api.js）互動    │
├──────────────────────────────────────────────────────────────┤
│ src/app      組裝層：S 共用狀態、hooks 擴充點、api、主迴圈     │
│ src/ui       介面        src/audio   音樂                    │
│ src/render   繪製：只讀取模擬結果與 Territory，不做歸屬判斷     │
├──────────────────────────────────────────────────────────────┤
│ src/core     模擬核心：純計算、可重現、不依賴瀏覽器             │
│   math → territory → universe → selfcheck                    │
└──────────────────────────────────────────────────────────────┘
```

依賴方向只能由上往下。`src/core` 不得 import 其他資料夾。

## 座標系

- **物理座標**：以「觀測者」所在的共動點為原點、隨膨脹放大的長度。有玩家宇宙時原點會跟著玩家（焦點跟隨，見下方 `rebase`）。泡泡在 `tn` 時於物理位置 `(x, y)` 誕生，之後中心為 `(x, y)·e^{H(t−tn)}`，
  半徑為 `R0·E + RH·(E−1)`（`E = e^{H(t−tn)}`，`RH = c/H` 為哈伯半徑）。這是平直切片的德西特時空中光錐的精確形式。
  向上穿隧產生的收縮泡泡（`s = −1`）半徑為 `r0·E − RH·(E−1)`，縮到 0 為止（見 docs/ROADMAP.md D6）。
- **螢幕座標**：`螢幕 = 畫面中心 + (物理 − P)·Z`。`P` 為攝影機中心（物理座標），`Z` 為縮放。
- `Territory` 的所有函式與座標系無關：同一套程式同時用在物理座標（縮放 1）與螢幕座標（縮放 Z）。

## 模擬核心（src/core）

- `createUniverse(p, tune, { actions })` 建立獨立的宇宙實例（`actions` 為要重播的動作紀錄）。
  - `p`（建立後不變）：`seed, H, RH, R0, RGEN, typical, vacN, crunchP, oddDimP`
  - `tune`（執行中可調）：`gamma`（穿隧率）、`innerMul`（口袋宇宙內部穿隧倍率）、`wallK`（疇壁速度倍率）
- 以固定步長 `STEP = 1/30` 秒推進（`U.advance(dt)` 會累積時間後逐步執行），因此與影格率無關、可用種子重現。
- 主要方法：`circleAt(b,t)`（**唯一的幾何來源**）、`aliveAt(t)`（直播與回放共用的存活清單）、`ownerAt(x,y,t)`、`observer(t)`、
  `crunchedAt`、`heatAt`、`shift`（疇壁位移）、`collideTime`、`act(a)`、`actionLog()`、`on('born'|'retire'|'act', fn)`。
- **泡泡**：`{ id, tn, x, y, d, vac, parent, depth, s, r0, texit, … }`。`s` 為泡壁方向（+1 擴張、−1 收縮），`r0` 為初始半徑，
  `act` 為 true 表示由使用者動作產生。
- **玩家宇宙**（可控制的泡泡，`b.ctl`）：軌跡以「每步一段」的解析式保存（`ctl.t/x/y/r/ux/uy/w`），`circleAt` 二分搜尋後代入
  `c(t) = (c₀ + u/H)·e^{HΔt} − u/H`、`r(t) = (r₀ + w/H)·e^{HΔt} − w/H`。`U.player` 為目前的玩家（`b.player`）。
  每一步（`playerStep`）：更新接觸區間 `ctl.contacts`、結算能量帳（`ctl.E`，格點取樣 + `Territory.locator`）、由控制器決定下一段。
  參數在 `PLAYER`（初始能量、效率 η、技能成本……）。玩家宇宙不退場；其他泡泡不會在它內部成核。
- **真空地景**：由種子生成的真空，最後一個固定是「激發態假真空」（`kind: 'up'`，比假真空高，只能由向上穿隧產生，以獨立亂數產生，不影響既有種子）。
- **動作紀錄**：`U.act({ type, … })` 在下一個固定步長的開頭套用、結果寫在 `a.result`，並保存在 `U.actions`（含步數）。
  動作不消耗主亂數序列，所以沒有動作時的歷史與原本逐位元相同；相同種子 + 相同動作紀錄 → 相同歷史。
  目前的動作：`nucleate { x, y, vac, r, by }`（目標真空較低 → 一般泡泡；較高 → 收縮泡泡；`by: 'player'` 為玩家技能，扣能量）、
  `spawn { x, y, vac, r, eta, mode }`（誕生玩家宇宙）、`steer { dx, dy, rT }`（玩家輸入）。擁有者一律由 `Territory.ownerAt` 決定。
- **歷史**：`hist`（依誕生時間排序）＋ `longs`（壽命超過 `LONG` 或永遠存在者）。回放視窗外、且已不可能存活的泡泡會被丟棄，記憶體有上限。
- **退場（retire）**：永遠不會流出範圍的巨大泡泡（吞沒了觀測者者），一旦在整個模擬範圍內已不可能再擁有地盤，就從下一步起退場。
  否則它們會累積、半徑無限增長、彼此的幾何失去精度。
- `EMAX = 1e13`：單一泡泡的膨脹倍數上限，只是最後的保險。

### Territory：歸屬的唯一定義

兩個無親緣關係、光錐相交的泡泡之間只有三種規則：

| 規則 | 條件 | 領域分法 |
|---|---|---|
| `merge` | 同種真空 | 「泡壁先到」平分（加權沃羅諾伊），不留疇壁 |
| `wall` | 不同真空 | 疇壁＝通過兩泡壁交點、向輸家（真空能較高者；相同時較早誕生者）鼓起的圓弧，隨 `U.shift` 推進 |
| `inherit` | 一方光錐整個在另一方之內 | 若內側較低能 → 不受限；否則沿用外側與「內側最近一個不在外側光錐內的祖先」之間的疇壁 |

有親緣關係者沒有規則：子泡泡永遠蓋在母泡泡上。

**繪製順序**：繪製鍵高者先畫，相同時較早誕生者先畫。繪製鍵 = 自己與所有祖先的真空能最小值：一般的家族中就是自己的真空能
（子泡泡能量必低於母泡泡，所以一定在上層）；向上穿隧的子泡泡比母宇宙高，沿用母宇宙的鍵，仍畫在母宇宙之上。
輸家因此畫在贏家之後時（`R.lYield`），輸家自己讓出贏家側；疇壁已越過輸家中心時（`R.cE`），輸家在贏家圓內的部分全部讓出。

**焦點跟隨（`rebase`）**：玩家離原點超過 `PLAYER.recenter·RH` 時，在步進的最後把原點換到玩家所在的共動點。
所有泡泡的誕生位置（與玩家的每段軌跡）減去該共動點在當時的位置，圓只差一個平移、物理不變；流出時刻以新原點重算（已退場者除外）；
發出 `U.on('rebase', { x, y, t })`，攝影機跟著平移，背景錨點在新舊原點之間交叉淡入（`S.anchorFade`、`scene.js` 的 `anchorList`）。
後選模式在有玩家時改以玩家為對象（誕生點離玩家泡壁不到一個哈伯半徑的泡泡不出現）。

**玩家宇宙**的泡壁比光速慢，「光錐被包住」不代表「早已被入侵」，所以與它有關的不同真空一律用 `wall` 規則的「推進前緣」版本（`R.ring`）：
玩家贏、或對方與玩家同種真空 → 玩家圓內全歸它（同種真空無縫融合）；玩家輸 → 贏家真空的前緣是以贏家中心為圓心、半徑 `U.ringR` 的圓（從接觸時刻起以疇壁速度推進），玩家只失去圓內的部分。

`Territory.locator(F, circles)` 對同一組圓只建一次規則、再查很多點（結果與逐點 `ownerAt` 相同），能量帳用它取樣。
每個泡泡的「繪製領域」由 `drawContains` 定義，`cellRay` 是它沿射線的解析版本。
**`ownerAt` 的定義就是「畫面上這一點最後被誰畫到」**，所以物理與畫面在定義上一致。

交界線（泡壁、疇壁、平分線）的可見性一律以「兩側實際顯示的宇宙」判斷（`displayOwner`），三泡交會處也能連續。

## 繪製（src/render）

每格流程（`render(t)`）：
1. 背景：假真空能量雲（三層無限縮放）、時空網格（含扭曲）、量子漣漪、哈伯視界
2. `collect(t)`：取出畫面附近的泡泡，轉成螢幕座標的圓，以 `Territory.buildRules` 建立規則
3. `drawBubbles`：依繪製順序畫內部（漸層、星空或能量雲、再加熱、大擠壓、熱寂），再畫泡壁、疇壁、交點閃光、標籤
4. `emit('render:world')` → 範圍邊緣霧與暗角 → `emit('render:overlay')`

巨大泡泡（半徑上億像素）一律只產生畫面附近的幾何（射線只掃過畫面所在角度、弧線改折線、漸層改線性近似），
被完全蓋住的泡泡不畫內部。

## 應用層（src/app）

- `state.js` 的 `S`：跨模組共用、且會被重新指定的狀態。主要欄位：

| 欄位 | 意義 |
|---|---|
| `U` | 目前的宇宙實例 |
| `HUB, RH, R0, RGEN` | 宇宙參數的唯讀鏡像（真正的值在 `U.p`） |
| `tView, isLive, playing, speed, scrubbing` | 播放狀態（`tView` 為畫面顯示的時刻） |
| `Z, minZ, zoomAnim` | 縮放（攝影機中心為 `render/camera.js` 的 `P`） |
| `vw, vh, dpr` | 視窗尺寸 |
| `qLevel, qMode, fpsCap` | 畫質 |
| `selected, vis, PAL` | 選取的泡泡、本格可見泡泡、各真空配色 |
| `simPaused` | 暫停演化（模擬本身停止；「播放／暫停」只暫停畫面時間） |
| `anchorFade` | 重新置中時背景錨點的交叉淡入狀態 |

- `hooks.js`：擴充點（事件）。`api.js`：外掛 API。`main.js`：`startApp`，依固定順序初始化各模組。
- `loop.js`：主迴圈。`stepWorld(dtR, draw)` 推進模擬並（視需要）繪製；背景運行時 `draw = false`。

## 建置

`build.mjs` 以 esbuild 把 `variants/<名稱>/main.js` 打包成 IIFE，連同 `src/styles/main.css`、
`variants/<名稱>/style.css`、`variants/<名稱>/extra.html` 一起內嵌進 `src/template.html`，輸出 `dist/<名稱>.html`。

## 不變式與檢查

| 不變式 | 檢查 |
|---|---|
| 同種子、不同時間切分 → 完全相同的歷史 | 可重現性 |
| 泡泡誕生處的擁有者就是它的母宇宙；只有仍在暴脹的宇宙能成核 | 成核合法性 |
| 物理判定的擁有者 = 畫面顯示的宇宙 | 物理與畫面歸屬一致 |
| 射線算出的邊界與逐點判斷吻合 | 繪製邊界正確 |
| 成核次數符合各區域的穿隧率 | 穿隧率正確 |
| 觀測者所在宇宙不會來回跳動；永久泡泡不累積 | 觀測者歸屬不跳回 |
| 畫面上所有不同真空相鄰處都有線 | 交界線連續 |
| 長時間、高膨脹率下數值有限 | 長時間數值穩定 |
| 疇壁不忽隱忽現 | 疇壁穩定 |
| 相同種子 + 相同動作紀錄 → 相同歷史；動作不消耗主亂數 | 動作紀錄可重現 |
| 使用者泡泡的母宇宙 = 放置處的擁有者；誕生後顯示在最上層；比母宇宙高者收縮並如期消失 | 手動成核合法性 |
| 向上穿隧時（輸家畫在贏家之後）歸屬、射線邊界、疇壁兩側仍然正確 | 向上穿隧的歸屬一致 |
| 玩家泡壁各點不超光速、軌跡連續 | 玩家宇宙：泡壁不超光速 |
| 維持大小的花費 = 2π·H·Δε·r²；η = 1 時移動淨收支為零 | 玩家宇宙：移動的能量收支 |
| 力竭時泡壁自由膨脹、不來回切換；大於哈伯半徑必定失控 | 玩家宇宙：力竭與失控 |
| 吞食較高真空得到能量、碰上較低真空失去能量並終被吞沒 | 玩家宇宙：吞食與被奪走 |
| 光錐包住玩家後仍只被逐步吃掉 | 玩家宇宙：被吞食是連續的 |
| 含操控與技能的動作紀錄可重現；玩家宇宙內不成核 | 玩家宇宙：可重現與不在內部成核 |
| 玩家在泡泡間移動時歸屬與射線邊界一致 | 玩家宇宙：歸屬一致 |
| 換原點只是平移：幾何、歸屬不變，範圍內的泡泡不被丟棄 | 焦點跟隨：平移不變 |
| 模擬區域跟著玩家；丟棄的泡泡永遠碰不到；含平移的重播一致 | 焦點跟隨：長途移動 |
| 仍包住玩家的泡泡不會因原點移動而被丟棄 | 焦點跟隨：進入大泡泡 |
| 重新置中時畫面不跳動、淡入期間仍在效能預算內 | 重新置中時畫面連續、重新置中淡入的繪製效能（瀏覽器） |
| 巨大泡泡的幾何留在畫面尺度、不拖慢繪製 | 巨大泡泡繪製（瀏覽器） |
| 泡內紋理移動速度有上限 | 紋理流速上限（瀏覽器） |
| 一般畫面每格 < 16 毫秒 | 繪製效能（瀏覽器） |
