# 開發歷程

本專案在與 Claude 的對話中逐步開發，共三個主要版本。第三版重構後模組化，成為之後所有版本的基底。
這份紀錄保留每個階段的需求、設計決策，以及踩過的坑與教訓，供日後開發參考。

## 第一版：模擬器本體

**目標**：具視覺與美術效果的永恆暴脹模擬器，呈現暴脹造成的空間扭曲與口袋宇宙；需要像直播的進度條（直播點在最前、可往回拖）與縮放平移。

**核心設計**
- 物理座標以一個「永遠留在暴脹區」的觀測者為原點（後選）。泡泡以光速擴張，中心隨哈伯流 `e^{Ht}` 外移。
  只有在哈伯半徑之外誕生的泡泡才不會吞沒觀測者，因此泡泡會貼著視界外緣長大、被膨脹帶走。
- 假真空能量雲用三層交叉淡入的無限縮放紋理，時空網格的線依 2 的次方逐層淡入，畫面上看起來持續向外流動。
- 量子漲落在視界內閃爍、被拉出視界後凍結成金色。
- 直播式時間軸：模擬在背景持續前進，畫面時間可以落後並回看。

**後續增修**
- 提供 HTML 下載；設定與說明可收起；開放更多參數（即時參數與需重新開始的宇宙參數分開）。
- 生成式音樂〈第一秒的永恆〉：D 利底亞和聲、謝帕德音階（後改為逐級上升，避免不和諧）、事件鐘聲。
- 資源控制：回放保留視窗（DVR）、泡泡數量硬上限、自動畫質、影格率上限、效能面板。
- 背景運行：以 Web Worker 計時，離開頁面仍繼續演化。
- 畫質預設改為「中」（自動調整可能造成畫面閃黑）。

**物理修正**
- 碰撞：泡泡不再重疊，改為「泡壁先到者擁有」的加權沃羅諾伊分區，交界是雙曲線。
- 大擠壓：以「內部時間 τ = 年齡·√(1−x²)」表現同時性 —— 從外面看，奇點區由中心向泡壁擴散，泡壁本身照常擴張。
- 教訓：用 Canvas 的 `clip()` 實作領域裁切非常慢（每格上百毫秒），改成「沿射線解析求邊界」的多邊形後回到數毫秒。

## 第二版：真空地景與更真實的物理

**新增**
- 真空地景（每個種子生成一組真空，物理常數屬於真空）。
- 同種真空融合；疇壁被能量較低的一方推動；正真空能的口袋宇宙內部繼續生出下一層；典型觀測者模式（不做後選）；
  大擠壓時間由真空能決定；亂數種子與固定步長（可重現）。
- 正真空能的口袋宇宙改畫能量雲（仍在暴脹，不會形成星系）。

**踩過的坑**（多數是「修一個、冒一個」）
1. 大擠壓宇宙似乎還在生泡泡 → 新泡泡的光錐被包在別的泡泡光錐內，碰撞判斷漏掉了。
   先用「禁止在別人的光錐內成核」修正，結果大泡泡光錐處處重疊，幾乎所有成核都被擋掉（第 7 點）。
2. 能量雲突然轉向、越流越快 → 紋理以融合群組根泡泡為中心縮放；群組一變中心就跳。改成以觀測者為中心、隨哈伯流流動。
3. 紋理忽隱忽現 → 每格紋理名額「先到先得」，分界不斷跳動。改成依可見面積分配並淡入淡出。
4. 碰撞面閃爍、不平滑 → 碰撞判斷有數量上限、射線數隨半徑連續變化、交界用折線近似。改為不設上限、射線數取 2 的次方、解析曲線。
5. 疇壁形狀：改為「通過兩泡壁交點的圓弧」，與泡壁平順銜接。
6. 擁有者判斷依候選順序而不同（非遞移）→ 依編號排序。
7. 典型觀測者模式越跑越卡、正真空能泡泡不生新宇宙 → 數值無限增長（半徑可達 10¹⁰⁷）與第 1 點的過嚴規則。

**教訓**：同一條規則（某一點屬於誰）在成核、畫面、點選、觀測者四處各有一份實作，是連鎖問題的根源。

## 第三版：重構

**核心改變**
- **歸屬只有一個定義**：`Territory` 模組；`ownerAt` 直接定義為「畫面上最後被誰畫到」，物理與畫面在定義上一致。
- **模擬核心可實例化**：`createUniverse`，純計算、可在 Node 執行，自我檢查用全新實例驗證。
- 存活清單合一（`hist` + `longs`）；參數分為建立後不變的 `p` 與可調的 `tune`。
- 自我檢查從 8 項逐步擴充到 12 項（見 docs/ARCHITECTURE.md）。

**之後的修正與功能**
- 不再暴脹（近零真空能）的宇宙不再成核；巨大泡泡只產生畫面附近的幾何、漸層改線性近似；完全被蓋住的泡泡不畫。
- 星空不再以外部暴脹速率放大（原本看起來越流越快）。
- `EMAX` 上限造成各泡泡在不同時刻凍結 → 相對幾何被扭曲、觀測者所在宇宙來回跳動。改以「退場」機制移除不可能再擁有地盤的永久泡泡。
- 被入侵中的子泡泡若能量較低，不受入侵者限制（低能量真空以光速推進）。
- 熱寂：近零真空能宇宙一直膨脹冷卻，從中心向外變暗；觀測者走到大擠壓或熱寂時提示「換個種子重新開始」。
- 泡內紋理流速上限（每秒 30 像素）。
- 疇壁：角度範圍重疊兩段時只取一段的錯誤；疇壁淡入淡出。
- 三泡交會處交界不連續 → 交界線可見性改以「兩側實際顯示的宇宙」判斷，並補上平分線。
- 效能優化（沒有第三方時跳過逐點判斷、依長度取樣、依繪製順序提早結束），最密集畫面由 44.7 降到約 26 毫秒；
  之後加入四項疇壁特效：粗細亮度反映能量差、雙色、推進漣漪、碰撞／融合瞬間發光。

## 模組化（本次）

- 單檔 HTML 拆成 `src/core`、`src/render`、`src/ui`、`src/audio`、`src/app` 多個 ES 模組；以 esbuild 建置成單一 HTML。
  拆分以工具依原始碼自動完成（依作用域分析改寫跨模組共用變數為 `S.xxx`、自動產生 import/export、保留原執行順序），
  並以像素比對驗證：關閉跨格累積的特效後，新舊版本的畫面逐像素相同。
- 新增擴充點（hooks）與外掛 API，範例外掛「檢視器」；`npm test`（Node 跑核心檢查）與 `npm run test:e2e`（瀏覽器）。

## 遊戲版的物理設計與控制版（M1、M2）

**討論與定案**（詳見 docs/ROADMAP.md D 節）
- 遊戲構想「有自我意識的宇宙」：靠位能差（潛熱）獲得能量、被較低真空奪走能量。
- 暴脹率 `H` 恆定，事件視界固定為 `RH`；泡壁間距 > `2·RH` 的區域永遠碰不到，所以「模擬區域跟著焦點」（A2）是精確的。
- 移動：控制膨脹方向（前脹後縮），泡壁各點不超光速；均勻假真空中移動淨能量為零；推得「越大越慢」`u_max = c(1 − r/RH)`。
- 操控暴脹場：不採用「整區改變 `H`」（2a：違反因果、永動機漏洞、核心所有預測未來的判斷都要改），採用「局部放泡泡」（2b）。
  2b 需要向上穿隧，因此需要「收縮泡泡」與比假真空更高的「激發態假真空」。
- 使用者介入只能在直播時；遊戲可暫停，結束後才能回放。

**實作**
- 動作紀錄 `U.act`：在固定步長邊界套用、記錄步數；動作不消耗主亂數（`hash(種子, 步數, 序號)`）。
  以修改前後的核心比對 4 個種子、300 秒的完整歷史與 400 點歸屬（md5），沒有動作時**逐位元相同**。
- 收縮泡泡：`r = r0·E − RH·(E−1)`，`texit` 取塌縮與流出的較早者；`collideTime` 對收縮泡泡改為逐步掃描（間距不再單調）。
- `Territory` 的繪製順序改用「繪製鍵」（自己與祖先真空能的最小值）；輸家畫在贏家之後時自己讓出贏家側（`lYield`），
  疇壁越過輸家中心時視為整個被吃掉（`cE`，維持領域對中心呈星形，`cellRay` 才能解析求邊界）。
- 控制版外掛：放置模式、游標預覽、暫停演化、動作紀錄重播與匯出匯入。

**踩過的坑**
1. 「物理與畫面歸屬一致」與「繪製邊界正確」對繪製規則本身的錯誤是**同義反覆**的：兩邊都用 `drawContains`，規則錯了兩邊一起錯。
   所以另加了直接檢查語意的項目：剛誕生的泡泡必須顯示在最上層、`lYield` 疇壁兩側各歸其主。
   並以「變異測試」確認：把繪製順序改回只看真空能、或拿掉 `lYield` 的讓出，新的檢查都會失敗。
2. 檢查「剛誕生的泡泡擁有自己的中心」時，一開始用了誕生時的座標 —— 但中心隨哈伯流移動，一步之內就可能移出半徑只有幾像素的新泡泡。
   檢查本身的錯誤也會造成大量假警報，先懷疑檢查。
3. 「未如期消失」的假警報：收縮泡泡可能在縮完之前先流出模擬範圍，`texit` 是兩者的較早者。

## 通用教訓

1. **一條規則只能有一份實作**。物理與畫面若各自判斷，遲早不一致。
2. **每修一個問題就加一項自我檢查**。視覺問題也能轉成可量化的檢查（交界線覆蓋率、閃爍次數、最大路徑座標）。
3. **注意「上限」與「快取」的副作用**：數量上限、膨脹上限、取樣上限都曾造成閃爍或跳動。
4. **視覺上的突兀常來自狀態瞬間切換**：淡入淡出、平順的相位累積比「正確但瞬間」的切換好。
5. **長時間運行要另外測**：很多問題只在典型觀測者模式演化數分鐘之後才出現。
6. **自我檢查要能抓到錯**：新增檢查後做一次變異測試（故意改壞），確認它真的會失敗；兩邊共用同一個函式的比對是同義反覆。
